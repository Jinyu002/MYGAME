# 战斗演出优化方案 · 2026-10-26

> 后续实施更新：P0-01/02及部分P1已落地，见 [v0.4结果](PRESENTATION_ITERATION_04.md)。以下“正式源码尚未应用”是研究阶段历史状态。

状态：诊断与第一轮参考研究完成；暂停机制已做隔离原型；**正式game源码尚未应用这些优化**。不改变现有玩法、素材或用户新装MCP。依据：[现状诊断](CURRENT_PRESENTATION_AUDIT.md)、[程序集证据D01–D15](DD2_MANAGED_RESEARCH.md)。

## 推荐方向

保留 `BattleRules → 已结算ActionRecord → Director → 展示反馈 → 完成屏障`。先让现有单次行动的暂停、变速、死亡、恢复可靠，再改善动作对比、镜头包围范围和弹字。不要为了使用“Timeline”这个名词迁移Unity、引入Cinemachine替代物或复刻参考状态机。

### P0-01 暂停与反馈时钟统一（必须解决，首选落地）

- **当前/问题：**main只暂停导演Tween和_process；弹字、死亡淡出、ActorView闪光继续更新。已在250ms暂停窗口复现。
- **参考依据：**D02/D06的统一routine和结束屏障、D12的暂停解绑说明生命周期应有明确归属；不声称原作全局暂停实现已完全验证。
- **方案/效果：**短期将战斗场景时钟暂停、菜单保持可处理输入；显式覆盖恢复、重试、标题和撤退路径。中期集中登记本次行动的反馈Tween，使变速和取消可统一控制；不要用Engine.time_scale同时加速菜单和全部应用计时器。
- **模块/风险：**main暂停入口、反馈创建和ActorView；中等风险。SceneTree暂停会影响Esc快捷键、音频和MCP运行时辅助，菜单必须PROCESS_MODE_ALWAYS并有独立恢复输入路径；不能直接把本轮两行原型作为完整产品补丁。
- **验收：**impact前/后各暂停250ms和5s，规则快照、镜头、弹字、alpha、flash、音频位置符合约定；1/2倍切换一致；按钮和Esc能恢复；暂停重试/撤退无残留。使用MCP与普通启动器各测一次。
- **美术：**不需要。**本轮状态：**隔离原型验证通过，未合并正式代码。

### P0-02 死亡反馈与恢复语义（必须解决）

- **当前/问题：**death独立淡出；导演恢复时无条件modulate=WHITE，死者在收镜阶段短暂重现。探针在当前与暂停原型中均复现，规则HP未改变。
- **参考依据：**D05/D06显式区分受击恢复、死亡等待、参与者重置；不是所有对象统一恢复可见。
- **方案/效果：**按record.after恢复最终存活/可见状态；将死亡Tween纳入行动拥有的反馈列表，取消/skip先终止旧Tween，再设置最终值，避免新旧写入竞争。最终状态由记录决定，不依赖是否实际播放了淡出。
- **模块/风险：**shot_director恢复、main死亡分支；低到中风险。不可过早隐藏而吞掉最后一次伤害弹字，也不能把死亡alpha复位影响到下一战重建。
- **验收：**单杀/群杀、流血杀死、skip、杀死后暂停、重试；每帧记录alpha，降至0后不得在下一次创建角色前恢复；最终BattleResult完全一致。
- **美术：**不需要；完整死亡动画属于P2。

### P1-01 明确准备、命中、短停与收势（显著改善）

- **当前/问题：**攻击姿态在切镜前立即出现；命中与持势几乎相接；interval/parallel分组不构成独占停顿。缺少动作速度对比和受击后回弹。
- **参考依据：**D03/D04语义信号和分项激活、D05受击/恢复；原版具体hit-stop时长未知。
- **方案/效果：**在现有导演增加明确顺序阶段，修正短停后必须chain再进入并行漂移；只用项目自定参数做A/B：准备约80–140ms、普通短停约30–45ms、暴击约45–65ms。数值为实验起点，不是反编译所得。受击用独立局部偏移，不改变阵位，miss使用闪避偏移，治疗不受震。
- **模块/风险：**presentation.json、shot_director、actor_view；中风险。多处Tween抢同一position会抖动，应把阵位/演出/受击偏移分层而非互相覆盖。
- **验收：**轨迹日志证明短停阶段位移不推进；2倍速仍保持事件顺序；音效、数字、受击同一语义点；正常/暴击/闪避各人工盲选A/B，不能仅凭截图判断冲击力。
- **美术：**首轮无需新图；准备和受击专属图可在P2补充。

### P1-02 保留远程语义的暴击修饰（低风险、高收益）

- **当前/问题：**critical直接替换ranged profile，远程暴击gap从1040变670，镜头不再保持射击空间。
- **参考依据：**D08条件相机与D10技能/目标条件构图；“暴击作为修饰”是本项目设计选择，不是已证实DD2原始结构。
- **方案/效果：**先取melee/ranged/support基础profile，再叠加暴击zoom上限、震幅、去色、持势修饰；不要覆盖基础gap或目标布局。
- **模块/风险：**配置和导演profile选择；低风险。需限制叠加zoom，防止群体镜头被再次放大裁切。
- **验收：**同一shot/volley种子构造普通和暴击记录，目标数量与射击距离稳定；特写结束完全归位。
- **美术：**无。

### P1-03 依据角色包围范围构图（局部原型先行）

- **当前/问题：**仅按目标人数缩小；固定脚底、680高和y965，不能覆盖未来宽武器/大体型。
- **参考依据：**D09成员权重/半径与观察空间范围、D10按体型调节偏移。
- **方案/效果：**从视觉配置取得有效绘制区和锚点，求参与者的并集包围盒，留顶部标题和数字安全区，计算2D相机中心/zoom，钳制最大1.44；特写开始确定构图，避免逐帧追逐弹字导致呼吸缩放。允许技能小幅偏移覆盖，不写角色名分支。
- **模块/风险：**资源元数据、导演镜头；中风险。透明留白不能算作角色体积，宽图不应造成角色过小；动态动画包围范围应预估而非每帧骤变。
- **验收：**4K/QHD的单目标、双目标、四目标，虚拟大/矮/宽角色，攻击图超宽但角色比例不变；UI无遮挡、zoom不跳；窗口/全屏切换需截图。
- **美术：**可先用现有图测alpha有效区；正式新增图需提供锚点和动作包围范围，无需立即新画角色。

### P1-04 弹字锚点、安全区与展示分组（局部修正）

- **当前/问题：**固定730高度与一次投影，之后镜头移动；多条信息被clamp到相同位置，长文本尺寸不受约束。
- **参考依据：**D13目标骨骼跟随、相机专用offset及回收。防裁切方案为本项目独立设计，未确认DD2采用同算法。
- **方案/效果：**数据使用head/chest锚点，先投影到HUD坐标再做文字实际尺寸布局；按目标分列，数值与状态分优先级，先整体平移避让再clamp。短暂跟随目标后固定屏幕位置，避免持续追镜造成难读；时间由行动反馈控制。
- **模块/风险：**main.popup可提取为小型反馈组件，art元数据；低到中风险。不可延迟关键伤害提示到下次行动，也不能为排队延长每次战斗过多。
- **验收：**负号、暴击+大数字、长中文、四目标多状态、屏幕两侧和顶部；4K/QHD文字Rect连outline保持在安全区，且不互相覆盖。
- **美术：**无。

### P1-05 换位与归位、适度结束屏障

- **当前/问题：**独立move有动画，攻击附带前进/后撤/推人却先回旧homes再refresh跳位；固定5秒看门狗未来可能截断长演出。
- **参考依据：**D06/D07等待阵位变化及按类别等待，D12临时偏移释放。
- **方案/效果：**恢复阶段目标使用record.after阵位；单独保留起始homes作为取消过渡信息。只等待本行动注册的关键位移/死亡反馈，纯装饰不阻塞；预算随配置总时长和速度推导，保留硬上限。不要因纯文字余辉未消失就阻断下一回合。
- **模块/风险：**导演、home_position布局入口、反馈登记；中风险。规则中的位置已经结算，不得在动画结束再重复move。
- **验收：**lunge/feint/shove、边缘换位、死亡压缩与换位同时发生；自然完成/skip/超时最终位置一致，规则revision不增加。
- **美术：**无；可先Tween位置，专用移动帧后补。

### P2-01 原创动作与音画节奏素材

- **当前/问题：**完整防御图作idle，单张攻击切换；没有准备、受击、收势或死亡序列，合成音色缺角色差异。
- **参考依据：**D05演员Animator反应、D11角色轨道绑定；不要求复制原作3D模型或Animator。
- **方案/效果：**先试制一英雄与一敌人，比较分帧或分层方案；先验证轮廓和锚点再扩到全阵容。准备/命中/收势音效分别映射语义节点。
- **模块/风险：**资源定义与ActorView，后续可能采用AnimationPlayer；中到高工作量，必须先验证替换规范，不能机械要求每角色相同帧数。
- **验收：**动作比例和脚底不漂、原图朝向一致、镜像后武器正确；同种子替换前后规则输出相同；4K/QHD截图和实机听感。
- **美术：**见下表，当前不是阻塞项。

### P2-02 多段技能/反击的表现事件序列（需确认）

- **当前/问题：**只有单impact，一次性消费所有事件；未来多段、多角色插入会显得同时爆发。
- **参考依据：**D01多PresentationIndex、D03标记、D11主攻击/反击轨道。但本项目当前尚未要求反击玩法。
- **方案/效果：**若确认需要多段演出，再引入只读ActionPresentationPlan，事件绑定唯一ID/语义节点，记录显示消费进度；不让动画修改规则。最初只支持固定有序片段，不先做通用优先级协程调度器。
- **模块/风险：**导演事件接口、main反馈、测试回放，可能跨多文件；高风险、需用户确认范围后实施。当前只列方案，不创建空框架。
- **验收：**跨帧skip、暂停/重试、乱序或丢失标记不得重复结算或漏最终显示；相同规则结果回放多种速度一致。
- **美术：**具体多段技能确定后再列，不提前制作。

3. P1-01/03/04/05分别做可切换A/B原型，依据截图/轨迹和体验选择；不能一次改所有参数后无法归因。
4. **须先确认的推荐决策：**是否启动P2-02多段表现事件接口，以及是否升级为分层/骨骼动画资源管线。当前推荐暂缓两项，先完成P0与P1。没有必须阻塞本轮交付的创意问题。
