# ADR 0001：独立工程根、纯规则与可替换表现

日期2026-10-25；状态：已采纳用于下一阶段实现，技术效果尚未实测。

## 背景

根目录是空Godot工程，study在其扫描树内且已有import文件。用户禁止任何写入study；参考资料只有配置与动画数据，不具备宿主执行器源码。要求长期扩展、4K优先、未来全面原创美术。

## 决策与权衡

1. **正式项目根game/**。不在study写.gdignore，不移动用户参考资料，不修改原根project。代价是工作区出现两个project.godot时须明确只打开game；README和后续启动脚本指向唯一正式入口。
2. **Godot 4.7.2 typed GDScript，2D + Compatibility原型**。利用现有引擎，无需新增C#环境或Spine付费运行库。对多层效果优先用2D实现；性能和视觉验证失败再升级渲染器，保留可回退配置。
3. **规则原子结算，表现回放事件**。相较动画回调扣血，命中时机展示需维护快照，但换图、快进、取消不会改变结算。只在表现屏障后接受下一行动，避免UI与规则跑两套进度。
4. **资源定义与运行时状态分离；visual_id映射素材**。Godot Resource便于编辑器配数据，RefCounted运行态避免共享配置被改写。暂不引入通用数据库、全局服务定位器或ECS。
5. **3840×2160设计，canvas_items + keep**。直接目标分辨率绘制UI，优先保证16:9构图；非16:9留边。真实设备/离屏验证分开记录。
6. **合法程序占位优先**。参考素材未获明确授权，不集成。A/B替换试验使用两套项目自制视觉即可，不依赖用户提交正式美术。
7. **原创战斗先确定可测规则**。阵位、状态与职业职责有研究依据，但公式/数值/时序独立制定；压力、尸体、死亡之门、永久死亡暂不纳入。代价是不能宣称忠实复刻原作，符合原创项目目标。

依据：REFERENCE_RESEARCH中的技能规则/美术分离、timescript集中恢复、镜头分层、AI定义引用，以及Godot官方多分辨率文档。重审触发：用户确定新画风、2D构图无法表达玩法、真实性能不达标、大型敌人/大量召唤、需要跨引擎版本重放或跨战持久化。
