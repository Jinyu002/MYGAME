# 分阶段路线图

所有阶段以退出门槛推进，非承诺日期；各阶段不逐项索要用户批准，重大创意或授权变化除外。

| 阶段 | 实际交付 | 退出门槛 | 当前状态 |
|---|---|---|---|
| P0 勘察研究与规划 | 只读索引、证据、GDD、架构、资源规范、验收计划 | 引用可定位，资料审计一致，未知机制/许可明确 | 本次交付 |
| P1 规则内核 | 独立game工程，定义/状态/命令/结算/AI/结果，自动测试入口 | 固定种子可复现，非法输入不改状态，所有状态/胜负边界通过 | 未开始，下一步 |
| P2 完整可玩闭环 | 初始化→选择→结算→演出→结果→重试；合法占位UI/角色 | 玩家能赢、输、撤退；输入不重复；异常演出可恢复；50轮兜底 | 未开始 |
| P3 表现与替换 | 镜头统一调度，打击/数字/音效，A/B资源配置 | 两重点分辨率截图+人工检查；换图不改规则；缺图回退 | 未开始 |
| P4 内容与平衡 | 完整4英雄/3敌类与预设4敌遭遇，技能与状态反馈 | 100种子自动战斗无锁死，人工≥10战记录策略/时长，修平衡缺陷 | 未开始 |
| P5 阶段交付 | 可运行工程/Windows包、操作说明、许可表、测试记录/已知问题 | 4K/QHD实测/离屏限制明确；重复启动/性能通过；可回退Git里程碑 | 未开始 |

P2先用一对角色纵向打通，再扩展至完整阵位；P4内容量不能掩盖P2流程缺陷。P3程序占位完成不等于正式美术完成，原创美术接入后重新做视觉验收。

后续候选：探索触发战斗→队伍成长/装备→任务与世界状态→存档。顺序取决于用户后续创意及实际依赖，不在本轮自动立项。

每个阶段更新：交付物、测试证据、缺陷、资源需求、下一步与需用户确认事项；不以代码行数作为进度指标。若阶段失败，先修根因，不将核心失败移到未来TODO宣称通过。
