## P1 规则测试矩阵

使用独立 `game/tests/run_tests.gd` headless入口（下一阶段实现），自有断言与失败退出码；不依赖连通的编辑器插件。相同定义与seed重复产生相同事件序列。

| 类别 | 必测情况 | 通过条件 |
|---|---|---|
| 数据 | 重复ID、缺技能、错引用、负HP、错误概率/阵位、缺视觉 | 规则错误启动前拒绝；视觉错误明确回退 |
| 先攻 | 平手、速度改变、队列中途死亡 | 每存活单位最多一次行动，排序稳定且版本可复现 |
| 输入 | 重复命令、旧revision、敌方回合点击、演出时连点 | 不重复扣HP/次数/RNG，返回可理解原因 |
| 技能 | 每项技能合法/非法阵位、友敌目标、群体目标 | 不漏/重复目标，预览与实际规则一致 |
| 命中伤害 | 0/100边界、暴击、护甲上限、最小伤、治疗上限 | 按GDD公式，舍入仅在指定步骤 |
| 状态 | 流血刷新/击倒、眩晕解除免疫、破甲扣次、坚守来源死亡 | 顺序确定、持续次数正确、不产生已死行动 |
| 阵型 | 两侧边缘移动、击退、死亡压缩、群攻致死 | entity_id目标不因压缩错打；队列顺序不重抽 |
| 结束 | 胜/负/同时无存活/撤退/50轮平局 | BattleResult只发一次，之后命令不再生效 |
| 确定性 | UI反复预览/AI评分/重放 | 预览不消耗战斗随机流，固定输入结果一致 |

概率逻辑优先用注入随机流命中边界测试，不用统计波动测试替代正确性；批量模拟用于发现死锁/平衡问题。

## P2–P5 集成与视觉

- 全流程：开始、取消选择、命中、未命中、状态、死亡、结果、重试、返回；重复100次自动会话，无残留输入锁或重复结果。
- 故障注入：缺攻击帧、缺音效、ActorView提前释放、结束信号缺失/重复、暂停恢复、快速重试；5秒看门狗后能恢复最新状态，旧回调不作用新战斗。
- 视觉：待机/准备/impact/受击/暴击/多人目标/死亡每个关键节点截图；人工确认武器/受击/数字/音效同步、无闪回跳位、镜头复位、UI可读。
- A/B替换：固定seed和命令的ActionRecord一致；不改核心代码；所有角色锚点、头像、技能映射、缺图回退检查通过。
- 分辨率：3840×2160、2560×1440、1920×1080及一个非16:9窗口。记录viewport实际尺寸，不将放大的截图冒充4K渲染。核查布局、字形、显示比例、图标、数字裁切、目标热区、缩放、全屏切换和资源模糊。
- 真4K显示器不可用时，渲染到4K离屏目标并保存原始PNG可验证构图；物理显示清晰度、DPI交互、全屏/刷新率仍标未验证。headless规则测试不产生视觉通过结论。
- 性能：记录CPU/GPU/内存/驱动/引擎/分辨率，预热10秒采样60秒；目标P95≤16.7ms、P99≤33.3ms。记录首次载入与第1/20/100场后的内存，调查持续增长；不预先宣称达到60FPS。
- 平衡：至少100个种子自动战斗无锁死，10场人工记录胜负、回合、耗时、常用技能、无效回合；5–8分钟只是调优目标，不能自动证明策略有趣。
- 发布：干净检出可导入/运行、包无study路径/未许可素材、中文字体无缺字、许可与署名齐全。

自动化无法判断画风一致与冲击力是否满意：给用户一战体验和关键截图，但先自行完成构图与技术检查，不让用户替代QA。
